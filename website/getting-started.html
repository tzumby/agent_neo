Getting started

This guide takes you from an empty AWS account to chatting with your agent. Steps 1 and 2 happen once, in the AWS and Tailscale consoles. Step 3 is a short run of make commands; the first deploy takes 15–20 minutes.

  1. Set up AWS
  2. Set up Tailscale
  3. Deploy
  4. Open the web app
  5. Start using it

Before you start

What gets deployed

Everything lands in your AWS account, in one region:

  • A VPC with private subnets. Outbound internet goes through a fck-nat instance (a t4g.nano), or AWS’s NAT gateway if you set enable_nat_gateway.
  • One desktop (a t3a.medium by default) in a private subnet: no public IP, no inbound rules, its own IAM role (SSM only) and its own KMS key for its disk. You administer it with SSM Session Manager; there’s no SSH.
  • An S3 bucket for Terraform’s state, one for Ansible’s file transfers, and two SSM parameters you create yourself: your model key and a Tailscale auth key.

Accounts

  • An AWS account. Step 1 walks you through a new one.
  • An Anthropic API key, from the Claude Console. The agent uses Claude Opus 4.6 by default, and you can switch to Opus 5.5 in the app. API use is billed per token; a Claude Pro or Max subscription doesn’t cover it, and its sign-in is only for Claude’s own apps. Prefer Together AI? Set agentd_llm_provider: together in ansible/inventory/group_vars/desktop.yml and run make model-key PROVIDER=together.
  • A Tailscale account. The free personal plan is enough.

Tools on your machine

  • AWS CLI v2With a profile that can create VPCs, EC2, IAM roles, KMS keys, S3 buckets and SSM parameters. Step 1 sets one up.
  • Session Manager pluginbrew install --cask session-manager-plugin, or see AWS’s install guide.
  • Terraform ≥ 1.10brew install hashicorp/tap/terraform
  • Ansible ≥ 2.17With boto3 installed in the Python that Ansible runs on. ansible --version shows which Python that is.
  • uvRuns the scripts that store your secrets in SSM.
  • RustInstall rustup; it fetches the pinned toolchain (1.93.1) on the first build.
  • zig and cargo-zigbuildcargo install cargo-zigbuild. Together they build agentd as a static Linux binary.
  • Go ≥ 1.27Builds tailnet-proxy.
  • Xcode 26 or laterOnly for the optional iPhone and Mac apps.

Check that they’re all on your path:

aws --version
session-manager-plugin --version
terraform -version
ansible --version
uv --version
rustup --version
zig version
cargo zigbuild --version
go version

Then get the code:

git clone https://github.com/tzumby/agent_neo.git
cd agent_neo

1Set up an AWS account

Give the agent an AWS account of its own, with nothing else in it. Whatever goes wrong there, whether it’s your mistake, the agent’s or this project’s, can’t touch your other AWS resources. The bill shows only this deployment, and you can close the account when you’re done.

Already have an AWS Organization with IAM Identity Center?

Create the account from the management account instead (AWS Organizations → Add an AWS account), assign yourself AdministratorAccess on it (the end of step 4 below), and carry on from step 5. Set the budget (step 3) in the management account, filtered to the new account.

The same goes for an account someone gives you inside their organization, such as an employer’s sandbox. Either way, the organization’s service control policies (SCPs) apply. They can block whole regions or services, even for an administrator; step 6 shows what they block.

  1. Sign up

    At aws.amazon.com, choose Create an AWS account. Use an email address no other AWS account uses; a you+neo@example.com alias works with most mail providers.

    Choose the Paid plan. The Free plan launches only a short list of small instance types, and neither the desktop (t3a.medium) nor the NAT (t4g.nano) is on it. Step 4 upgrades the account anyway, because enabling IAM Identity Center creates an AWS Organization.

  2. Lock up the root user

    While signed in as root, add MFA (a passkey or an authenticator app) from the account menu at the top right: Security credentials → Assign MFA device. Never create access keys for root. After step 4 you need root only for billing and account settings.

  3. Set a budget

    So you hear about a desktop you forgot to stop before the card statement arrives. Go to Billing and Cost Management → Budgets → Create budget → Monthly cost budget. Pick an amount a bit above the running cost (about $40 a month), say $60, and add your email.

    Then, from the account menu: Account → IAM user and role access to Billing information → Edit → Activate IAM Access, so the admin user from step 4 can see costs too.

  4. Create an admin user in IAM Identity Center

    The CLI then uses short-lived credentials that expire on their own, not long-lived access keys in ~/.aws/credentials. First pick the region you’ll deploy to (top right of the console), since Identity Center lives in a single region.

    • IAM Identity Center → Enable. In a standalone account this creates an AWS Organization with the account as its management account. That’s expected.
    • Users → Add user, with your email. Accept the invitation email, then set a password and MFA.
    • Permission sets → Create permission set → Predefined permission set → AdministratorAccess. PowerUserAccess isn’t enough, because Terraform creates an IAM role for the desktop.
    • AWS accounts → tick the account → Assign users or groups → your user → AdministratorAccess.
    • On the Dashboard, copy the AWS access portal URL (https://d-xxxxxxxxxx.awsapps.com/start).

  5. Add a CLI profile

    Run aws configure sso. Your answers look like this:

    $ aws configure sso
SSO session name (Recommended): neo
SSO start URL [None]: https://d-xxxxxxxxxx.awsapps.com/start
SSO region [None]: ca-central-1          # where you enabled Identity Center
SSO registration scopes [sso:account:access]:
  (a browser opens: sign in, allow, then pick the account and AdministratorAccess)
Default client Region [None]: ca-central-1
CLI default output format [None]: json
Profile name [AdministratorAccess-123456789012]: neo-sandbox

    Check that the profile reaches the new account:

    aws sts get-caller-identity --profile neo-sandbox

    A sign-in lasts 8 hours by default. After that, run aws sso login --profile neo-sandbox again. Terraform, Ansible and the scripts all use this profile through AWS_PROFILE.

  6. Check the account with make preflight

    From the repository:

    export AWS_PROFILE=neo-sandbox AWS_REGION=ca-central-1
make preflight

    It only reads, and creates nothing. It shows which account and identity you’re using, then checks that you’re allowed to make the deployment’s calls in that region (under your IAM policies and your organization’s SCPs), that the desktop’s instance type is offered in two availability zones there, and that EC2’s vCPU quota covers the desktop and the NAT (4 vCPUs).

    Fix whatever it reports before going on. Troubleshooting covers each case.

2Set up Tailscale

The desktop answers only on your tailnet. In the Tailscale admin console:

  1. Turn on MagicDNS and HTTPS

    Under DNS, turn on MagicDNS and HTTPS Certificates.

  2. Create a tag for the desktop

    Access controls → Definitions → Tags → Create tag. Set Tag name to neo-agent (without tag:) and Tag owner to autogroup:admin, then Save tag. In the JSON editor, that’s "tag:neo-agent": ["autogroup:admin"] under tagOwners. A tagged device doesn’t expire with your login.

  3. Generate an auth key

    Settings → Keys → Generate auth key, tagged tag:neo-agent, and pre-approved if you use device approval. Keep it handy for step 3. tailnet-proxy uses it only the first time it joins; after that, the node keeps its own identity.

  4. Put your devices on the tailnet

    Install Tailscale on each laptop and phone you’ll use the agent from (tailscale.com/download) and sign in with the same account. Only devices on your tailnet can open the web app. The iPhone and Mac apps join the tailnet by themselves, so a device that only uses an app doesn’t need the Tailscale app.

With the default access rules, every device of yours on the tailnet can reach the desktop. If you share your tailnet with others, limit it to named logins after you deploy, or tighten your rules.

3Deploy

Run these from the repository, in order, one block at a time. Several of them stop to ask you something.

  1. Point the Makefile at your account

    export AWS_PROFILE=neo-sandbox AWS_REGION=ca-central-1

    Export these in every new shell. If AWS_PROFILE isn’t set, the Makefile uses your default profile, which on many machines points at some other account. make preflight shows which account you’re about to deploy to and warns you when AWS_PROFILE isn’t set.

  2. Prepare Ansible and Terraform

    Once per deployment. Install Ansible’s AWS collections:

    make galaxy

    Create the S3 bucket for Terraform’s state. Terraform shows what it will create and asks you to type yes:

    make bootstrap

    Then point Terraform at that bucket:

    make init

  3. Create the infrastructure

    Plan first, and read what it will create:

    make plan

    The plan is saved, and make apply applies exactly that plan, without asking again. It creates the VPC, the NAT and the desktop in a few minutes:

    make apply

    Afterwards, give the desktop a minute or two to register with SSM before step 5.

    The first instance launch in a new account, or in a region the account hasn’t used, can fail with PendingVerification while AWS checks the account. It usually clears within minutes but can take a few hours; then run make plan and make apply again.

  4. Store your two secrets

    Each command asks for a value with hidden input and stores it as a SecureString in SSM. Run them one at a time.

    make model-key

    Paste your Anthropic API key. Then:

    make tailscale-key

    Paste the auth key from step 2.

  5. Set up the desktop

    make deploy

    This configures the desktop (OS hardening, the display stack, Chrome), then installs agentd, then puts the desktop on your tailnet with tailnet-proxy. The first run takes 15–20 minutes. It ends by printing the web app’s address:

    ok: [i-0123456789abcdef0] => {
    "msg": "The web app: https://neo-agent.tail1234.ts.net (open it on a device on your tailnet)"
}

    Each playbook run starts with two warnings, “The 'tags' host variable is deprecated” and “Found variable using reserved name 'tags'”. They’re harmless.

Optional: let in only named logins

To let only specific Tailscale logins reach the desktop, enter them comma-separated, then redeploy tailnet-proxy:

make tailscale-allow
make tailnet-deploy

4Open the web app

Open the address make deploy printed in a browser on any of your devices that has Tailscale running. You don’t need to remember it:

make url
  • The first load can be slow while Tailscale issues the site’s certificate.
  • On a phone, add the page to your Home Screen to use it like an app.
  • Notifications: under Settings → Notifications, turn them on for each device you use. You’ll hear when a card needs you, when a site needs you to sign in, when a chat task that ran over a minute finishes, and when a scheduled run finds something. On iPhone or iPad, add the web app to your Home Screen first (Share → Add to Home Screen), open it from there, then turn them on; iOS only allows web notifications for Home Screen apps.

5Start using it

Ask for something in the chat. The agent works in its own browser and shell; three dots mean it’s working, with how long it’s been at it, and Stop cancels the task.

  • PlansAnything with three or more steps gets a checklist that ticks off as the agent goes.
  • Approval cardsShow the exact command, browser input or app input the agent wants. Every click, bit of typing and key press needs your OK, and typing and submitting are separate cards.
  • PlansWhen a task would ask again and again, the agent shows its plan first, on one card: each step, with the site, app, commands, saved key or install it needs your OK for. Reword, add, remove or reorder steps, take off anything you’d rather approve one at a time, then approve. What’s left goes ahead without more cards until the task ends, and each action shows in the chat as Under your plan. New sites and direct internet still ask on their own. And on any card, Allow for this task approves it and stops cards like it until the task ends: no more for that site, that app, or commands and the key they use.
  • Signing in to sitesWhen a site needs you (a login, 2FA, a CAPTCHA), an Action needed card offers Take over. The desktop opens in the page, and the agent carries on when you’re done. Chrome stays signed in.
  • Keys and tokensGive them through the secure card or the Keys and tokens screen, never in the chat. Review the exact command before granting a key, and prefer narrowly scoped tokens: the command runs in the agent’s workspace, so anything there it uses (a tool the agent installed, a repository’s git hooks, package scripts) runs with the key too.
  • Desktop appsBeyond Chrome, the agent uses the desktop’s own apps: it clicks, types, presses shortcuts and fills dialogs, each batch on one card. It can also install apps from the Snap Store, with your OK. See Desktop apps.
  • Schedules“Every weekday at 8, summarize my inbox” or “tomorrow at 9, check PR 12”. Each run’s answer lands in the chat; the Schedules screen pauses and cancels them.
  • MemorySend remember rule: …, remember preference: … or remember fact: … for standing instructions, and forget #ID to remove one. The Apple apps add a Memory screen to confirm, edit, import and export.
  • Long tasksThere’s no step cap. A supervisor checks in every 30 minutes of work or 60 model turns; if a task looks stuck, you get a Looks stuck card with the reason, and choose Keep going or Stop.
  • Local serversThe agent’s commands reach the internet only through the proxy, and nothing on the desktop itself, not even a dev server the same command started. Run those checks on your own computer.
  • Auto approveOff by default, in Settings. When on, ordinary shell commands and schedule setup run without a card. Browser and app input, saved keys, new sites, direct internet and data going out after reading outside content still ask.

The agent also reads short how-tos (“skills”) when it needs them: installing software with Nix (never curl | bash), Python with uv, Node, git and GitHub, opencode with Together AI, and deploying to Fly. They live in services/agentd/skills.

The iPhone and Mac apps

Optional native apps for iPhone (iOS 26 or later) and Mac (macOS 15.6 or later, Apple silicon), in apps/apple. They have the same chat as the web app, a native take-over view with the phone’s keyboard and gestures or the Mac’s keyboard and pointer, and a Memory screen. Each app has its own Tailscale node built in: you sign in with Tailscale inside the app, and it finds your desktop by its tag:neo-agent tag.

What you need, on a Mac

  • Xcode 26 or later, from the App Store. Open it once to finish installing.
  • XcodeGen: brew install xcodegen.
  • Go, as for the deploy; it builds TailscaleKit.
  • Your Apple Account in Xcode: Xcode → Settings → Accounts → +. A free account works for building and running, but apps it signs stop opening after 7 days until you build again. With the Apple Developer Program ($99 a year) they last a year, and only a paid account can create the key that notifications need.

Build and install

  1. Build the Tailscale node the apps embed

    Once; it takes a few minutes.

    make app-tailscalekit

  2. Find your Apple team ID

    With no APPLE_TEAM_ID set, this lists the teams your Mac can sign for, each as a line like export APPLE_TEAM_ID=A1B2C3D4E5:

    make app-project

    Run the line for the team you want. Like AWS_PROFILE, export it in every new shell.

  3. Build and install

    The Mac app installs to /Applications and opens:

    make app-mac

    The iPhone app installs to an iPhone connected by cable (the first time, see below):

    make app-device

    These builds have no notifications, which keeps them working on a free account. The bundle ID is dev.neoagent.app.<your team ID>; set APP_BUNDLE_ID to use another.

The iPhone, the first time

  1. Connect it to the Mac with a cable, unlock it, and tap Trust.

  2. Run make app-device. If it says Developer Mode is off, turn it on in Settings → Privacy & Security → Developer Mode (the iPhone restarts), then run it again. The setting only appears once a Mac with Xcode has seen the phone.

  3. With a free account, trust your certificate before the app will open: Settings → General → VPN & Device Management → your Apple ID → Trust. Then open Agent Neo from the Home Screen.

Signing in: tap Log in with Tailscale and sign in with the account your desktop is on. The app joins your tailnet as neo-agent-iphone or neo-agent-mac; approve it in the admin console if you use device approval.

Notifications for the apps (Apple Developer Program)

agentd sends notifications to Apple directly with your own APNs key: no push relay, nothing extra in AWS. A free account can’t create an APNs key or use the push entitlement.

  1. Create an APNs key

    In your Apple developer account: Certificates, Identifiers & Profiles → Keys → +. Name it, tick Apple Push Notifications service (APNs), Continue, then Register. Download the .p8 file (you can only download it once) and note its Key ID and your Team ID.

  2. Give the key to your desktop

    make apns-key   # asks for the .p8 path, the Key ID and the Team ID
    make agentd-deploy

  3. Rebuild the apps with notifications on

    APP_PUSH=1 make app-mac
APP_PUSH=1 make app-device

    Open a signed-in app and allow notifications when it asks; it registers itself with the desktop from then on.

Desktop apps

Beyond Chrome, the agent uses the desktop’s own Linux apps the way you would. It reads their controls through the accessibility tree that screen readers use, with Microsoft Research’s open-source Hybrid Computer Use, and then clicks, types (any language, newlines included), presses shortcuts, picks from menus, fills dialogs, scrolls, and switches or closes windows.

Each batch of input is one card, unless you approved a plan that names the app. It lists every step: the full text to type, each key, each control and where it sits. You also get the agent’s reason and a screenshot. Everything is checked again just before it happens: if anything changed while you decided, nothing is sent. It never types into password fields, and scheduled runs can’t use apps.

The apps it may use are listed: Mousepad and Slack to start. Chrome stays with the browser tools, and terminals and the file manager are out of reach.

On and off

It’s on for x86 desktops (desktop_apps in ansible/inventory/group_vars/desktop.yml): make deploy installs the pinned Hybrid Computer Use release (its checksum checked), Mousepad, and a small broker that only agentd can talk to. It stays off on arm64, which Hybrid Computer Use doesn’t ship for yet. To turn it off, set desktop_apps: false and run make deploy.

Turning it on or off restarts XFCE and Chrome once: the desktop’s session moves to a different message bus. Chrome’s open tabs close; your sign-ins stay.

Try it

  1. Take over the desktop and open Mousepad (Applications → Accessories → Mousepad). The agent doesn’t start apps itself.

  2. In the chat, ask: “In Mousepad, write a shopping list with three items and save it as list.txt in my home folder.”

  3. Approve the plan card: its steps name Mousepad, so the typing, Ctrl+S and the file name in the Save As dialog then go ahead without more cards, each listed in the chat as Under your plan. If the agent goes ahead without a plan, or you take Mousepad off it, you approve each batch instead: two or three cards, each showing the desktop as it was when the agent asked. Mousepad’s title changes to list.txt.

Reading needs no card: “What does the file open in Mousepad say?”

Screenshots

With a model that sees images (Claude Opus; on Together, Kimi-K3), the agent also looks at screenshots of the desktop, zooms into them, and can click, drag or type at a spot on the screen, for anything the accessibility tree leaves out. Those cards number each spot on the screenshot. On Together, the default model, GLM-5.3, doesn’t take images, so the agent works from the tree alone.

Installing apps

Ask the agent to install a desktop app, like Spotify or Zoom. It looks the app up in the Snap Store and asks on a card that shows the app, its publisher, version and size. Only sandboxed apps from verified publishers qualify. Once you approve, it’s installed with launchers on the desktop and in the Applications menu. Installing an app doesn’t let the agent use it: add the app to the list below first.

Adding an app

Apps are listed in agentd_desktop_apps_allowed (the agentd role’s defaults): the app’s accessibility name, its executable, the name you know it by and, for one that isn’t from the store, its package. Never list an app with a shell in it, like a terminal, an editor with a terminal panel or a file manager that opens one: typing there would run commands as the desktop user, outside the agent’s sandbox. The design notes show how to find an app’s names.

Updating

git pull
make agentd-deploy    # agentd (copies its database first)
make tailnet-deploy   # tailnet-proxy and the web app
make desktop          # OS hardening, the display stack, Chrome

If you use the apps, rebuild them too:

make app-mac app-device

To rotate the model key, run make model-key, then make agentd-deploy.

Backups

Set enable_desktop_backups = true in terraform/personal/terraform.tfvars, then run make plan and make apply. Amazon Data Lifecycle Manager then takes a daily snapshot around 03:00 UTC and keeps the latest seven. EBS storage charges apply.

Snapshots contain the desktop’s chat, memory, saved keys and Chrome profile. They use the desktop’s KMS key and stay in the deployment’s account and region, so keep that key available for recovery. Older snapshots can still contain data you’ve deleted from the desktop.

Restore drill

  1. In EC2 → Snapshots, choose a completed snapshot with the NeoAgentBackup tag for your deployment. Confirm the source volume and timestamp, and note the snapshot and KMS key IDs.

  2. Create a temporary encrypted volume from that snapshot in the availability zone of a trusted recovery instance, and attach it as a data volume. Leave the production desktop and its root device untouched.

  3. On the recovery instance, use lsblk -f to find the restored Linux root partition. For ext4, mount it with mount -o ro,noload. Copy /var/lib/agentd/agentd.db and its -wal file, if there is one, to an encrypted scratch directory with restricted access. Run sqlite3 agentd.db 'PRAGMA quick_check;' on the copy and expect ok.

  4. Unmount, detach and delete the temporary volume and the scratch data once you’ve verified the result. After replacing the desktop or turning backups off, inspect older snapshots by hand: Data Lifecycle Manager stops pruning them.

Plus what you spend on the model: Claude Opus 4.6 is $5 per million tokens in and $25 out, Opus 5.5 $4 and $20, and input read back from the cache costs a tenth of that or less. make stop brings the desktop’s part down to its disk. Unlimited CPU credits (cpu_credits) can add to it under sustained load.

Teardown

make destroy

Then, by hand:

  • The state bucket stays (prevent_destroy); delete it in the S3 console if you want it gone.
  • Delete the SSM parameters under /neo-agent/personal/.
  • Remove the desktop, and the apps’ devices neo-agent-iphone and neo-agent-mac, in Tailscale’s admin console.

Troubleshooting

  • The agent says no window of an app it may use is open

    Open the app from the desktop (through Take over) after the desktop has started: apps that were already open when its accessibility switched on may need closing and opening again, and the agent says which. If it still can’t see them, make shell and check systemctl status neo-desktop-broker.

  • make preflight says the region is blocked by an SCP

    It lists the regions the SCPs allow. Change AWS_REGION to one of them and run make preflight again. Anything else an SCP blocks needs the organization’s administrator.

  • make preflight says your IAM policies don’t allow a call

    Give your user or role AdministratorAccess (step 1, item 4).

  • The vCPU quota is under 4, or make apply fails with VcpuLimitExceeded

    New accounts can start with low EC2 limits. Go to Service Quotas → Amazon EC2 → Running On-Demand Standard (A, C, D, H, I, M, R, T, Z) instances → Request increase at account level, and ask for 8. Some SCPs also block reading the quota; if yours do, go ahead and watch make apply.

  • make apply fails with PendingVerification

    AWS is still checking a new account or region. It usually clears within minutes but can take a few hours. Then run make plan and make apply again.

  • Commands are hitting the wrong AWS account

    AWS_PROFILE isn’t exported in this shell, so the Makefile fell back to default. Export it again; make preflight shows which account you’re on.

  • AWS commands fail after a few hours

    Your SSO sign-in expired (8 hours by default). Run aws sso login --profile neo-sandbox.

  • make deploy can’t reach the desktop right after make apply

    The desktop takes a minute or two to register with SSM. Wait, then run make deploy again.

  • The web app is slow to load the first time

    Tailscale is issuing the site’s certificate. Give it a moment; later loads are quick.

  • The app says “No desktop yet”

    No device tagged tag:neo-agent is online. Check that the desktop is running (make start) and that make url prints its address.

  • The iPhone or Mac app stopped opening

    Apps signed with a free Apple account last 7 days. Run make app-device or make app-mac again.

  • APP_PUSH=1 builds fail to sign

    A free Personal Team can’t use the Push Notifications capability. Notifications for the apps need the Apple Developer Program.
